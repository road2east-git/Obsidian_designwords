# 비교 분석: RAG vs LLM 위키 패턴

[[RAG]](Retrieval-Augmented Generation)와 [[karpathy-llm-knowledge-base-pattern|LLM 위키 패턴]]은 모두 개인/조직의 문서에서 지식을 추출하는 방법이지만, **지식의 처리 시점과 축적 방식**에서 근본적인 차이가 있습니다.

## 핵심 차이점 비교

| 구분 | RAG (전통적 방식) | LLM 위키 패턴 (Karpathy 제안) |
|------|-------------------|-------------------------------|
| **지식 처리 시점** | **Query Time (질문 시)**<br>질문이 들어올 때 문서를 검색하고 조합 | **Ingest Time (수집 시)**<br>문서를 추가할 때 미리 읽고 위키를 갱신 |
| **지식의 형태** | 파편화된 원본 문서 조각 (Chunks) | 구조화되고 상호 연결된 마크다운 위키 |
| **지식의 축적** | 없음 (매번 처음부터 새로 조립) | 있음 (영속적인 아티팩트로 누적/복리 효과) |
| **복잡한 추론** | 여러 문서를 횡단하는 미묘한 추론에 약함 | 이미 문서 간 교차 참조와 종합이 완료되어 있어 강함 |
| **유지보수 주체** | 검색 엔진 / 벡터 DB | LLM 에이전트 (IDE처럼 작용) |

## 왜 위키 패턴이 더 나은가?

RAG 시스템(예: NotebookLM, ChatGPT 파일 업로드)에서는 아무리 좋은 통찰을 얻어내더라도 그 세션이 끝나면 사라집니다. 다음 번에 비슷한 질문을 하면 LLM은 다시 원본 조각들을 뒤져서 똑같은 종합 과정을 거쳐야 합니다. 

반면 LLM 위키 패턴은 LLM이 발견한 **모순, 연결고리, 통찰을 위키 파일 시스템에 명시적으로 기록(commit)**합니다. 지식이 일회성으로 소비되지 않고 영속적인 코드베이스처럼 관리됩니다.
