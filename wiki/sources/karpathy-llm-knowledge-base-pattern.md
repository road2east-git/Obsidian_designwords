# LLM 기반 개인 지식 베이스 구축 패턴

> 원문: [Karpathy Gist](../raw/karpathy-llm-knowledge-base-pattern.md)

## 핵심 주장

기존 [[RAG]] 방식은 질문할 때마다 원본 문서에서 관련 조각을 검색해 답변을 생성하므로 **지식이 축적되지 않는다**. 이 패턴은 LLM이 **점진적으로 구조화된 위키를 작성하고 유지보수**하여 지식이 복리로 쌓이게 한다.

## 3계층 아키텍처

1. **Raw Sources** — 원본 문서 모음. 불변(immutable). 진실의 원천.
2. **Wiki** — LLM이 전적으로 소유하는 마크다운 파일 모음.
3. **Schema** — 위키 구조와 워크플로우를 정의하는 설정 파일 (예: `AGENTS.md`).

## 3가지 핵심 작업

- **Ingest**: 새 소스 추가 → LLM이 요약 + 위키 전반 업데이트. 하나의 소스가 10~15개 페이지를 건드릴 수 있음.
- **Query**: 위키 기반 질문 답변. 좋은 답변은 위키에 새 페이지로 저장하여 탐색 결과도 축적.
- **Lint**: 주기적 건강 점검 — 모순, 고아 페이지, 누락 링크 발견.

## 핵심 인사이트

> "지식 베이스 유지의 지루한 부분은 읽기나 사고가 아니라 **관리 작업**이다. LLM은 지루해하지 않고, 교차 참조를 잊지 않으며, 한 번에 15개 파일을 수정할 수 있다."

- 역할 분담: **사람** = 소스 선별, 방향 설정, 질문 | **LLM** = 요약, 교차 참조, 파일링, 관리
- [[Obsidian]]을 IDE로, LLM을 프로그래머로, 위키를 코드베이스로 비유
